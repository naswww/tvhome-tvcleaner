# 04 · 清理器、停用基线与开机守卫

## 一个常见误区

很多「电视清理器」只是执行 `am force-stop` / `am kill-all` 然后报一个好看的数字，
既不校验是否真的停掉，也不管会不会把桌面一起停掉。判断真假清理看三点：

1. 有没有**清理后复验**（重读 `ps` 逐包确认）
2. 有没有**白名单**（尤其是否包含当前默认桌面）
3. 有没有**持久化**（重启后停用状态是否被系统改回去）

## 清理器的几个硬伤与修法

| 硬伤 | 后果 | 修法 |
| --- | --- | --- |
| 白名单不含自建桌面 | 深度清理把首屏停掉，掉到直播或 FallbackHome | 把桌面、投屏、直播、设置、输入法、系统 UI 全部加入 `KEEP` |
| 跳过所有 OEM 系统包 | 看似保守，其实漏掉可清理项；但**必须**保留输入相关系统服务，否则遥控器 HOME 键失效 | 按功能分类，而不是简单按包名前缀一刀切 |
| 清理后不校验 | 报告「已清理 12 项」实际一项没停 | 清理后重读 `ps`，输出 `X/Y really stopped` |
| `drop_caches` 需要 root | 无 root 设备上静默失败 | 诚实报告不可执行，不要假装成功 |
| 拉起鼠标用 `am start-foreground-service .../.MouseService` | 目标包根本没有 Service Resolver，命令无效 | 用 LAUNCHER intent 拉主界面，随后发 HOME intent 把桌面带回前台 |
| system uid 进程停不掉 | `pm disable-user` 已禁用但框架仍拉起 | 无法用 shell 解决，报告为「不可停止」而不是谎报成功 |

## 预装包停用基线

```bash
adb shell pm disable-user --user 0 <pkg>     # 用户级停用，重启后保持
adb shell pm list packages -d                 # 读回实际停用清单
adb shell am force-stop <pkg>                # 仅会话级，不是持久停用
```

设计要点：

- **分批执行**，每批 `sync` + 重启验收，不要一次禁用几十个
- 维护一份 `BASELINE`，开机守卫对比 `pm list packages -d`：
  发现漂移就重新停用并复验
- 守卫结果**落盘**到 `/sdcard/Android/data/<pkg>/files/`，
  因为本机第三方 logcat 不可见，不落盘等于黑盒
- 守卫同样用 `BOOT_COUNT` 门控，每次开机只跑一次

> `BASELINE` 是硬编码的示例清单：以后新增停用包必须同步更新，否则会被守卫「修复」回去。
> 换机型时请整份替换。

## 权限与能力的诚实边界

- `pm disable-user --user 0` 对普通第三方/预装包有效且重启后保持
- 对 **system uid（1000）** 进程无效：状态显示 disabled，框架仍按白名单拉起
- 无 root 时不能写 `/system`、不能改开机白名单、不能读其他应用私有目录
- 所以「清理器能关掉所有常驻服务」是不成立的，报告里要如实区分

## 交互设计（供参考）

六个按钮，按风险从低到高排列：刷新自检 → 标准清理 → 深度清理 →
清理并打开视频应用 → 恢复遥控鼠标 → 清单校验/修复。
前三个是常规操作，最后一个是「体检 + 修复」，不要把修复藏在清理动作里。
